# A2 — measured offline-runtime feasibility; backend selection still open

## Reproduction

```
python -m pip install psutil==7.1.3
python tests/test_stem_runtime_benchmark.py
python tools/benchmark_stem_runtime.py --runtime /path/to/stems-split \
  --model /path/to/htdemucs-42M-v1.0-F16.gguf --out build/model-evidence \
  --seconds 2 --threads 1 4
```

Actual runtime: stems.cpp v0.1.6 (`0a003317cec3a333a45f3c6670c4437c22db605f`),
ggml `b77ae790`, Linux x64 GCC14.2 Release CPU build. Model SHA-256 and full
commands/input hashes are in `evidence/2026-11-07-htdemucs-linux.json`.
CPU exposed by this container: AMD EPYC 9V74, three logical CPUs, cgroup quota
`200000 100000` (two CPU equivalents). This is not a physical Windows benchmark.
Tests/build activity shared the environment; these are diagnostic baseline runs,
not isolated sustained qualification.

| Input | Threads | CLI inference | Wall incl. load/I/O | Inference RTF | Peak RSS |
| --- | ---: | ---: | ---: | ---: | ---: |
| 44.1 kHz, 2s | 1 | 20.00s | 20.094s | 10.00 | 733.9 MiB |
| 44.1 kHz, 2s | 4 | 12.36s | 12.432s | 6.18 | 734.0 MiB |
| 48 kHz, 2s | 1 | 19.02s | 19.130s | 9.51 | 734.0 MiB |
| 48 kHz, 2s | 4 | 12.48s | 12.586s | 6.24 | 734.1 MiB |

RTF here means **seconds processing / seconds input**; <1 would be necessary
but insufficient for streaming. Existing CLI reports its internal inference
clock separately from cold wall time. Peak RSS/CPU are sampled every 20ms;
Windows includes OS peak working set when available. CPU may omit its last
sampling interval. No GPU was measured. No real-time host workload was measured.

All cases emitted four finite stereo WAVs. At 44.1 kHz, summed-output minus
input RMS = 0.00390945 FS, peak = 0.0275026 FS, relative residual = -30.0524 dB.
This synthetic diagnostic **does not measure isolation, SDR, bleed or musical
quality**. CLI converts 48k input to model 44.1k, unlike the C ABI which promises
input-rate output. The harness leaves 48k reconstruction null rather than
comparing misaligned rates or claiming the plugin already resamples correctly.

## Consequences for implementation

The current full-context HTDemucs call cannot be selected as a real-time backend
on this configuration: inference costs >6 times the input duration, even before
host scheduling. Its 7.8s model segment is internally padded for short clips;
submitting short windows does not make it a causal low-latency model. Repeated
CLI launches are **not** a streaming implementation. Keep HIGH QUALITY/OFFLINE.
The callback fallback/timebase is implemented in A1, but no separator is wired
into `processBlock`, no latency preset has been chosen and no Live UI is enabled.

Windows workflow runs the same real model at 44.1/48k, with 1/default CPU threads,
and uploads JSON, original inputs, four outputs and runtime logs. It retains the
existing 9s inference smoke and complete VST3/GUI/pluginval/package checks.
Windows numbers must be reviewed separately before claiming that gate passed.

## Current source/license checks and candidate status

- stems.cpp v0.1.6 README and `src/libstems_v1.h`: synchronous `separate`,
  one context per caller, model native 44.1k, progress/cancel between ~7.8s
  segments; C ABI resamples output back to input rate. An adapter could run
  this on a worker, but moving a slow call off-thread does not meet deadlines.
- stems.cpp model card `docs/model-cards/htdemucs-GGUF.md` identifies Meta MIT
  code/weights and source checkpoint `955717e8-8726e21a.th`; F16 affects only
  transformer matmul tensors, with measured parity loss relative to F32.
  Training-data permissions remain separate from the runtime license. The
  benchmark uses the already selected model; it bundles no additional model.
- StemgenRT source checked at `7d2d0c19d956f67259b8358c4127f991077e02b0`:
  `licenses/WEIGHTS-LICENSE.md` explicitly licenses v0.7/v0.8 weights under
  CC BY-NC-SA 4.0 and does not represent commercial clearance for MUSDB18-HQ/
  MoisesDB. No weights or code were copied into MasterLabX.
- Its `docs/parallel-workers.md` reports 224 missed results / 40,400 Windows
  callbacks at 128 samples, and six underruns / 20,200 callbacks at 256. Even
  published 1.525ms mean inference does not establish deadline qualification.
  This supports A1's bounded queues, timestamp rejection and aligned fallback.
- Streaming SCNet/Band-SCNet, causal lightweight models and ONNX remain research
  candidates; **not benchmarked, selected, imported or licensed for this build**.
  The prior research report's papers are references, not measurements here.
- Context7 JUCE guidance confirms variable/zero blocks, callback-only playhead
  access, `isNonRealtime` for bounce and latency reporting during initialization.
  Actual integration must verify JUCE8.0.6 source, PDC and FL Studio behavior.

## Open gates (not complete)

A2 still requires a distributable candidate passing Windows sustained streaming
benchmarks with known musical multitracks, lookahead/latency, state continuity,
underrun, CPU/RAM and quality evidence. A3/B–F and the new live Windows installer
are not complete. There is no FL Studio installation in this Linux environment.
No existing release or unrelated branch was changed or merged.
