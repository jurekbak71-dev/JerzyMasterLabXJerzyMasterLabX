# Live Stem Brain — A1 callback boundary

This implements a tested callback/worker boundary, **not a live neural separator**.
The plugin still follows its existing offline path until A2/A3 pass their gates.
No APVTS IDs, plugin identity, GUI or existing DSP behavior changed.

## Existing callback graph (base 334e7a0)

- `Processor::prepareToPlay` configures/prepares SerialGraph, meters and Brain,
  resets StemRemix, reports SerialGraph latency and allocates host bypass delay.
- `processBlock` / `processBlockBypassed` call `renderAudio`.
- `renderAudio` snapshots graph parameters; reads current host time/playing flag
  inside the callback (offline renders also run when `isNonRealtime()` is true).
- `StemRemix::render` optionally replaces/adds imported WAV audio before the
  mastering graph. Its fallback position advances only while rendering stems.
- The resulting signal fills input/host bypass scratch in chunks of <=128;
  Brain captures that input, SerialGraph processes it, host bypass crossfades,
  then meter/response/analyzer queues publish output.
- A3 must capture the incoming buffer **before** StemRemix modifies it; its
  transport fallback must not depend on imported-bank playback. Combined PDC
  must include live delay and SerialGraph delay, including host bypass.

## New boundary contract

`LiveStemEngine::prepare(rate, latency, fade)` allocates fixed delay storage on
control thread, with both audio and worker quiescent. Rates 8–384 kHz and latency
0–65535 samples are supported by this slice. This is a storage/configuration
limit, not a chosen model latency. Larger-context backends require an explicit
capacity/memory decision before integration. Fade must be nonzero.

A single audio thread calls `process` and `reset`; a single worker calls
`popInput` and `pushOutput`. Existing `LiveStemQueue` is reused, with two bounded
65536-frame SPSC queues. Queue ownership is never reset concurrently. Audio
reset changes an epoch in O(1), invalidating tagged delay history and worker
results without clearing potentially large buffers or destroying memory.

Positions in frames are unsigned sample offsets within an epoch, independent
of signed DAW time (including negative preroll). Seek, loop, start/stop, timeline
availability and realtime/offline transitions create new epochs. Missing host
time uses a local sample clock. Stopped input remains delay-aligned dry monitoring;
`nonRealtime` submits input even if host playing is false. Workers must retain
frame positions/epochs and return increasing positions; gaps are permitted.
Input overflow is counted and dropped without blocking. Future output within
current input time is held; corrupt impossible-future, stale, nonfinite and
unrepresentable summed output is rejected with bounded work (max eight queued
frames examined per sample).

Delayed original and stem sums share the same timestamps. No result means a
linear fade of the last audible correction to dry. Returning results fade from
the current correction. Digital silence suppresses held/hallucinated content.
Extreme finite host/worker values that overflow final mixing fall back to finite
delayed dry and clear the correction. This short hold is an outage concealment
tradeoff; musical quality and click-free behavior for an actual backend still
require waveform/listening validation. It is not a restoration algorithm.

## Reproducible checks

```
cmake -S . -B build-core -DMASTERLAB_PLUGIN=OFF -DCMAKE_BUILD_TYPE=Debug
cmake --build build-core --parallel 4
ctest --test-dir build-core --output-on-failure --parallel 4
g++ -std=c++20 -O1 -pthread -Wall -Wextra -Werror \
  -fsanitize=address,undefined -fno-omit-frame-pointer -ISource \
  tests/LiveStemEngineTests.cpp Source/LiveStemEngine.cpp -o build-core/live-asan
build-core/live-asan
```

Tests exercise hand-derived three-sample delay across variable/zero blocks,
mono duplication, signed preroll, seek/stop/start, stopped offline render,
starvation/recovery ramps, invalid model output, silence, overflow, zero callback
allocations (including reset), concurrent worker/seek stress, impossible future
metadata and extreme finite fallback. The recovery and finite-output/future
regressions were observed failing before fixes. Checks remain active in Release.
An independent code review reproduced the extreme fallback overflow; that bug
now has its own regression.

`live_stem_benchmark` outputs p50/p99/max callback times at 44.1/48/96 kHz and
32/128/257/1024-sample blocks in starved/full-input, identity fixture and stale
backlog scenarios. Fixtures are fed outside the timed callback; there is no
neural model or concurrent inference. The CSV is **boundary cost only**, not
CPU qualification, a host deadline guarantee, end-to-end latency or live AI
separation evidence. Windows CI uploads its own CPU metadata and CSV.
